## 不能直接按 valid() 拒绝结果删数据

使用现有生成器的 `valid()` 扫描下载输入，统一换行并忽略文件末尾空行后，33 题出现拒绝记录。
其中上表 20 题确认违法；另外 10 题存在校验器适用范围较窄的问题：

| 题号 | 校验器与题面的差异 |
| --- | --- |
| 18160 | 额外限制组数 `T<=100`，题面未给此上限。 |
| 18177 | 额外限制 `N<=20,D<=30`，题面未给这些上限。 |
| 19493 | 要求行内小数位数一致，并排除部分尾零价格；题面允许一位或两位小数。 |
| 19963 | 额外限制房屋数 `n<=1000`，题面未给此上限。 |
| 23568 | 把时长计算为结束日减开始日，错误拒绝当天开始、当天结束的一天计划。 |
| 28276 | 校验器 `n<50`，题面 `n<=500`。 |
| 29468 | 只接受非负整数字符，题面未禁止负整数。 |
| 30159 | 只接受生成器的空行/满行构造，不适用于一般数织；独立约束推导已确认 27 对下载数据均有唯一解。 |
| 30162 | 排除了含其他字符的非法表达式；题面要求对错误表达式输出 `WRONG`。 |
| 30899 | 额外要求 `a<b` 且端点对唯一；另行允许平行边做拓扑排序，31 个文件的 DAG、范围和结构都通过。 |

这 10 题不能仅因当前 `valid()` 拒绝就删除；这也不意味着它们已经完成全部语义验收。
31069 的现有校验器展开 `A×B`，不适合扫描大数据；改用字符频数计算结果串长度后，31 个文件的输入结构和询问下标均通过。

另有 3 题暂不定性：

- 16531：`0.in` 的空答题行会被筛查的末尾空行归一化删去，属于筛查假阳性；`20.in` 中空答题行和非空答题行并存，题面未明确未答题编码与行长要求。
- 18104：包含重量 0；描述同时写了 `0<=g,s<=100` 和“正整数”，需先消除题面矛盾。
- 20102：包含圆周点数 0；题面未写下界，校验器要求至少 1，需明确是否允许 0。

## 闸门覆盖缺口

当前 `full_sweep` 的输入契约检查主要针对生成器自身的数据，不能证明下载输入满足契约。
参考解审核测试仍围绕旧 archive 的 158 题，新增题的文件哈希检查不能替代答案检查。
20091 已证明这一缺口可以放过错误答案；上表证明参考解 AC 本身也不能替代输入合法性检查。

抓取脚本另有同长度更新漏抓问题：`fetch_gmyhf_testdata.py` 按 Content-Length 相等就跳过正文。
离线伪响应已复现本地 `old`、远端 `new` 都为 3 字节时仍保留 `old`。此次未修改抓取脚本。
同一离线复现中，`force=True` 可以正确刷新；修正脚本前重抓应使用 `--force`。
漂移分类还使用文件内容哈希集合，忽略配对与重复次数：30912 被标为 exact，但实际从 5 对变为 4 对，减少的是重复数据；未发现该题错配。
