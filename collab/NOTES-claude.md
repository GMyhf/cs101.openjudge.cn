## 2026-07-24 · T-002 任务书：LLM 生成缺失测试数据（Codex 实现，Claude 复核）

### 背景与目标

项目本意：把 cs101.openjudge.cn 现代化，提供「编写 → 提交 → 反馈错在哪组数据」的
完整闭环。判题闭环已通（`judge.py` 会报 `case: N`），瓶颈是数据覆盖：catalog 1863 个
条目中 918 个 `test_cases` 为空（按去重全局题号 535 个）。目标：给这些题目生成
可信的测试数据，目录命名 `<题号>_made` 标记出处。

### 现场事实（开工前必读）

1. **`data/openjudge/tests/` 在本克隆不存在**（未跟踪目录）。catalog.json 里的 945 条
   已索引数据来自别处的一次索引。→ 人先恢复 tests 树；恢复前**严禁跑
   `scripts/index_tests.py`**，否则它按磁盘现状重建，会把 945 条全部清成空。
2. 缺数据题目清单以 **catalog.json 中 `test_cases == []`** 为准，开工时重新导出一份
   （人口头说 818 有/1045 无，catalog 说 945/918，以机器导出为准，差异在批次报告里说明）。
3. 题面在 `data/openjudge/pages/<book>__<id>.html`，结构干净：
   `<dt>描述/输入/输出/样例输入/样例输出</dt><dd><pre>…</pre></dd>`，且含「全局题号」。
   **注意本地 id 后缀数字 ≠ 全局题号**（例：`pctbook/E03406` 的全局题号是 2407）；
   `index_tests.py` 按**本地 id 的尾部数字**匹配目录名，目录必须用这个数字。
4. `index_tests.py` 的目录正则是 `(\d+)`，`4102_made` 天然被索引成 4102，索引器不用改。
   但 bucket 是固定集合（`1000-1999`…`30000-`），若题号落在缝隙里（3683-3999、
   8211-9999、19964-19999），需扩 `BUCKETS`——扩了要在交接里说明。

### 工作方式

- 模版：`tools/make_data_template.py`（我起草的；**人若提供自己的模版则以人的为准**）。
  每题一个 `make_data.py`，放进 `tests/<bucket>/<题号>_made/` 一起入库存档——
  它就是数据的出处证明，也是我复核的对象。索引器只 glob `*.in`/`*.out`，不受影响。
- 模版的自检是第一道闸门：`solve()` 必须复现题面样例（原样复制，一字不改），
  跑不过就不许落盘。
- **只给没有真实数据的题目生成**；一题多库（同一全局题号出现在多个 book）只生成一份。
- **多解题不生成**：本地判题是 token 精确比对，构造题/任意解/浮点题会误判 WA。
  识别出来就跳过，题号进「需 special judge」清单，留给后续任务。
- **分批**：先 20 题试点 → 交我复核 → 通过后按 ~100 题/批放量，每批交接一次。
  每批报告：生成数（题号列表）、跳过数及原因分类、samples 自检全过的证明
  （批量跑一遍 `make_data.py` 的汇总输出）。
- tests 树恢复后、每批合入后：跑 `scripts/index_tests.py`，报告前后计数。

### 我的复核标准（先说清，免得返工）

1. 抽样读题面 vs `solve()`：算法是否真的解这道题（这是唯一无法机器化的部分，
   我会重点花时间在这里）；
2. 复跑 `make_data.py`：可复现（固定种子）、样例断言真的在跑；
3. 数据形状：有最小/最大边界组、规模不超判题限制（CPU 4s / 输出 2MiB）；
4. 用 `judge.py` 真判：拿参考解法当提交，走一遍真实判题路径拿到 Accepted；
   再故意改错一行，确认能拿到 WA 且 `case` 指对组号（反馈闭环是本项目的本意）；
5. 「需 special judge」清单抽查：是否真的多解，还是偷懒漏做。
